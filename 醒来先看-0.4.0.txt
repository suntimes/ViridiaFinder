维里迪亚寻宝 0.4.0：醒来先看

安装
退出 Minecraft，用本次 viridia-finder-0.4.0.jar 替换 mods 中旧版 Viridia Finder；只保留一个版本。需要 Minecraft 1.20.4、Fabric、对应 Fabric API 和 Java 17 或以上。本次没有替换你游戏目录里的 JAR。

正常使用
1. 进入主群岛 monumenta:isles。F7 同时开启扫描、箱子高亮、右上角地图；约两秒后规划海面巡查。再次 F7 一起关闭，并关闭移动辅助。
2. 跟随海路航点，自己控制方向。到站不是必须手动检查每一个候选点：模组优先扫描该站覆盖的已加载候选区域，完整扫描后自动推进；途中已完成一组也可重新规划以减少绕路。
3. 右上角“巡查 N/169”是本轮实际完成的候选数量，不是预计覆盖数量，也不是找到的宝藏数量。逐站完成不再刷聊天；新发现箱子和重要状态仍可提示。
4. F8 查看结果，点击“海面巡查”可重新规划。只找普通箱子和陷阱箱，不再检索木桶。箱子仍需要玩家确认是否本轮宝藏。
5. F8 的“轮次／激流／游泳”打开辅助设置。正常左键一次主手的维里迪亚之眼，读取系统提示即可更新轮次信息；不用每次手打新一轮。

轮次怎么自动判断
支持你截图中的中文提示，以及原英文提示。只接受手动使用之眼后的短时间窗口内的系统信息。
已领取数量下降，或新的刷新估算明显进入下一轮，可开始新本地记录。第一次读取也会比较旧记录建立时间与本次提示推算的轮次起点：明显属于旧轮才更新，并保留五分钟估算余量。
只显示“4/4 已领取”不会立刻清空；倒计时归零也不会直接清空。旧记录留档。规则依赖公开说明的两小时周期和 NPC 的估计，不是服务器轮次编号，不能保证识别所有情况。
看不到提示、出现未支持的翻译格式、同一维度切换不同分线而没有区分实例，都可能影响判断。手动新一轮保留作备用。不能仅凭一个方向确定全部四个宝藏；之眼只追踪其中一个。

连续激流与游泳
两项默认关闭，不保存为自动开启。需要时自己在 F8 打开。
连续激流已去掉人为两秒等待，正常蓄力约十个游戏刻后释放，再按原版条件尝试下一次；失败尝试限频。仍受正常蓄力、水/雨、附魔、耐久、服务器冷却与延迟约束，不能承诺实际零间隔。
自动向前游泳现在会提供前进输入和正常疾跑请求，不再只是设置疾跑标志。跟随你的视角，不会沿巡查路线自动转向。需要正常入水条件，游泳姿态由游戏决定，不能在岸上或不满足条件时强制保持。
后退、潜行、攻击、打开界面或失去窗口焦点会暂停辅助；F7 关闭、死亡、离开世界会关闭辅助。关闭时如果已开始蓄力，停止使用可能释放最后一次激流。
未进行服务器内实测；这些移动辅助是否被服务器许可尚未确认。不会修改速度、坐标、强制姿态或绕过冷却。

搜索效率与海路
不把“16 区块”当作事实。开启时检查客户端实际完整加载圈，扣除边缘余量和候选扫描半径，以覆盖多处候选的海面扫描站规划路线；不强制加载区块。
固定测试起点 X=-763、Z=1321：
- 假设完整加载圈16区块，覆盖半径232格：41站，海路约21906格，169候选均有覆盖安排。
- 假设完整加载圈8区块，覆盖半径104格：97站，海路约35466格，169候选均有覆盖安排。
这只是规划测试，不是服务器实测时间，也不是全局最短路线证明。未实际完整扫描的候选不会因为“预计覆盖”就算完成；等待补扫仍无法完成会缩小规划范围重新规划。

地图来源和未解决的限制
已读取你的 Xaero 主群岛地表缓存，生成四格分辨率水域网格；只保留连通海域，避开已知陆地和未知区域。没有读取缓存中的宝藏状态。
本版本将这次水域快照打包进 JAR，不是实时读取 Xaero。服务器地形变动或尚未记录的水域不会自动补全；狭窄水道可能被保守排除。源代码中提供导入脚本，更新快照需要重新编译。
从陆地出生点先提示最近海面入口；海面入口之后才是海路。地图只说明历史地表通行，不能保证实时没有障碍或三维障碍。找不到水路时明确保留待处理，不自动画穿大陆的直线。
本轮通过99项程序验证，包括真实Minecraft方块类型、Fabric混入加载和海路覆盖，但没有启动游戏窗口或连接服务器验证游泳手感、实际激流频率、HUD布局。不要将编译通过理解为全部实机效果已经验证。
